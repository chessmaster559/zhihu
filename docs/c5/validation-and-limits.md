## BME690 实机结果

基础版在 ESP32-C5 上确认地址 `0x76`、chip `0x61`、variant `2`，官方
自检 `PASS result=0`。首个样本为 `status=0xa0`，热板未稳定，未计入有效气体。
后续记录出现 `status=0xb0`、`gas_valid=1`、`heater_stable=1`。

下列摘录来自传感器日志，已去掉网络、设备身份及无关会话内容：

```text
Bosch self-test: PASS result=0
Configured: chip=0x61 variant=2 addr=0x76 I2C=100kHz forced/3s heater=300C/100ms
Sample=4  gas=7988ohm status=0xb0 gas_valid=1 heater_stable=1 valid_gas=3  errors=0 stack_min_B=2680
Sample=45 gas=7181ohm status=0xb0 gas_valid=1 heater_stable=1 valid_gas=44 errors=0 stack_min_B=2680
Sample=80 gas=8390ohm status=0xb0 gas_valid=1 heater_stable=1 valid_gas=79 errors=0 stack_min_B=2680
```

这些记录证明基础采集与热板有效性，不能据电阻大小评价空气优劣。样本 80 时
累计错误为 0；有效计数 79 与首帧排除一致。采集任务最低剩余栈 2680 B。
运行期间有 Wi-Fi 连接、EAF 播放和音频采样，不等同于长期满负载压力测试。

## 其他已有运行证据

- 联网后资源加载成功，出现 `pet_greeting / pet_idle / pet_sway / pet_play / pet_sleep`
  的 `mode=eaf128` 记录，昼夜场景按睡眠切换。
- 麦克风多个持续窗口交付约 15769–16153 Hz，读取错误为 0；切换状态跨窗的
  交付率不能直接解释为 ADC 采样时钟变化。
- 触摸已有 `idle → connecting → listening` 与 `listening → idle`，因此“只见爱心”
  至少有一次是监听反馈不足，而不是按下链路丢失。最新源码增加等待绿点。
- 曾观测内部 SRAM 历史最小 14308 B；这是包含尚未关闭 BMI270 任务的基础版，
  不能直接作为最新模式互斥版的内存数据。
- 原配 BME690 模式下旧版 BMI270 每 10 秒探测失败；最新源码停止这一任务。

用户反馈“可以闻到但无法分辨气味”；这不是已经捕获到 `Query:` 的证据，
也不是完成气味分类测试。当前尚无训练模型，反馈与能力边界一致。

- 100 项主机测试通过，覆盖构建配置、打包、控制器口令/时序、重试、音量、
  场景时间边界与触摸手势等。新文档提交前重新执行该套件。
- ESP-IDF v6.1 的 C5 规范构建通过，随后最新 UI 修改的增量构建通过。
- C5 板级鼻子关闭/桌宠开启、鼻子开启/桌宠关闭、两者均关闭语法检查通过。
  关闭桌宠后的 LCD、OLED、基础 Display/NoDisplay 路径检查通过。
- 实际 LVGL 32 位离屏渲染验证字幕、UTF-8 截断、特效生命周期、夜间染色、
  脚部落点、爱心不遮字、监听点两级可见性及堆完整性，`checks=0`。
- 官方 EAF C 解码器此前已验证六组共 540 索引帧的像素、alpha、时长与低内存清理。
  这些是主机验证，不是屏幕帧率测试。
