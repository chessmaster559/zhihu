# C5 桌宠回退修复（2026-10-09）

本次只构建 ESP-SensairShuttle / ESP32-C5。上次发布没有保住已有桌宠与
麦克风功能，不能把素材转换成功、固件编译成功当成整机功能验证成功。

| 用户现象 | 代码原因 | 修复 |
| --- | --- | --- |
| 出现小尺寸通用表情 | 显示仍接受通用 `SetEmotion()`，服务器表情能覆盖画面 | 专用桌宠入口只选择六组 128×128 `pet_*` EAF；启动、配网及失败回退使用 128×128 黑白照 |
| 麦克风失效 | 烧录版本保留了 ADC 初始化的 `#if 0` 旁路 | 启用官方 `esp_codec_dev` ADC DMA，16 kHz / ADC1_CH5；输入任务拥有启停，增加错误退避和直流偏置处理 |
| 原动作组合不再运行 | 桌宠控制器没有接入构建和应用事件，转换素材没有恢复动作逻辑 | 接回状态、时钟、用户 STT、触摸及动作完成事件；播放回调只投递到主任务 |
| 相同音量值更响 | 原分贝曲线被替换为线性百分比增益 | 恢复 -50..0 dB 曲线、0 静音及原有效 HP DIV2；保留 NVS 音量值 |

动作规则：正常启动打招呼一次，随后待机；待机 10 秒进入晃悠/玩耍；
30 秒没有用户语音进入瞌睡。“帮我…”触发电脑，“你好”触发打招呼，
“睡觉”触发瞌睡。服务器表情、TTS 及语音服务状态切换不会重启动作。
一次动作结束以播放器完成回调为准，事件序号拒绝旧动作回调；解码失败和
缺失回调有超时退路。BMI270 无子板时只重试，不阻止其他功能。

## PDM 噪声的软件调整（2026-10-10，本地未烧录）

原代码已经通过 IO 矩阵产生反相信号，因此此前引脚和启停修正不能视为
新增差分输出。Wi-Fi 电流经功放供电或地回路耦合是可能原因，尚未证实。

- 改用官方 `I2S_PDM_TX_CLK_DAC_DEFAULT_CONFIG`，去除手动覆盖的
  `fs=480`。24 kHz PCM 对应 `fp=960/fs=240/bclk_div=13`，名义 PDM
  速率由 3.072 MHz 改为 6.144 MHz；启动日志打印这些配置，尚未测量实际频率。
- C5 功放空闲关断门限由 120 ms 延长至 300 ms，以跨过短网络停顿，减少
  启停次数。仍需播放/解码队列排空，正在写入时不能关闭。此改动不增加 PCM
  缓冲，但可能延长播报结束后的可闻底噪窗口。
- 保留已有 10 ms 淡入。队列暂空不能可靠表示句末，这轮未据此增加淡出，
  以免截断网络分包语音。可靠收尾淡出需要播放链路提供明确结束标记。
- 未增加音频缓冲；引脚、麦克风采集、原分贝增益曲线及桌宠逻辑未改动。

ESP-IDF v6.1.0 的 C5 规范构建通过，应用大小 2,494,464 B，最小应用
分区剩余约 40%。96 项主机测试及格式检查通过，包含 300 ms 门限的边界、
新写入续期、队列未排空和写入中禁止关闭等检查。
日志在 `tmp/c5_noise_20261010/build.log` 和 `tests.log`。
